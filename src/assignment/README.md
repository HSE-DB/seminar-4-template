# Самостоятельное задание. База данных и SQL-клиент

Соберите небольшой Compose-проект: PostgreSQL создаёт таблицу из SQL-файла, отдельный клиент подключается по сети и выводит число строк. Проверьте, что данные сохраняются после удаления и создания контейнера.

Заполните [compose.yaml](compose.yaml) и [init.sql](init.sql). Настройки находятся в [.env.example](.env.example). Файлы этого задания независимы от стенда методички.

## 1. Сервер db

Используйте образ `postgres:18` и настройки из `.env.example`:

| Переменная | Значение |
| --- | --- |
| POSTGRES_USER | student |
| POSTGRES_PASSWORD | student |
| POSTGRES_DB | practice |
| PG_PORT | 55434 |

- Передайте `POSTGRES_*` серверу через `environment` с подстановкой из файла окружения.
- Опубликуйте `5432` контейнера на `127.0.0.1:${PG_PORT}` компьютера.
- Объявите именованный volume `pgdata` и подключите его к правильному пути PostgreSQL 18.
- Подключите `./init.sql` только для чтения к `/docker-entrypoint-initdb.d/10-init.sql`.
- Добавьте healthcheck на основе `pg_isready` по TCP `127.0.0.1`.

Не задавайте `container_name`, фиксированные имена volumes/networks и `external`: ресурсы должны принадлежать текущему Compose-проекту. Используйте обычную сеть проекта.

## 2. Начальные данные

В `init.sql` создайте таблицу `users`:

| Поле | Требование |
| --- | --- |
| id | Целочисленный первичный ключ, значение генерируется автоматически |
| name | Текст, NOT NULL |
| age | Целое число, NOT NULL |

Добавьте ровно три записи:

| name | age |
| --- | ---: |
| Alice | 20 |
| Bob | 30 |
| Carol | 40 |

## 3. Клиент client

- Используйте образ `postgres:18` и профиль `tools`.
- Передайте клиенту `PGHOST=db`, `PGUSER`, `PGDATABASE` и `PGPASSWORD` из настроек сервера.
- Задайте зависимость от `db` с условием `service_healthy`.
- Запускайте `psql` с запросом количества строк в `users`. Используйте формат без заголовков и выравнивания, чтобы stdout содержал только число и перевод строки.
- Клиент завершается после запроса с кодом 0. Публикация портов и mounts у него не нужны.

## 4. Самостоятельная проверка

Из папки `src/assignment/` выполните:

```bash
docker compose --env-file .env.example config --quiet
docker compose --env-file .env.example up -d --wait db
docker compose --env-file .env.example run --rm client
```

Ожидается `3`. Добавьте ещё одну запись через SQL-консоль, выполните `down` без `-v`, снова поднимите сервер и запустите клиент. Должно быть `4`.

Для проверки с чистыми начальными данными удалите **только volume этого задания** через `docker compose --env-file .env.example down -v`. Не используйте данные других проектов.

## Автотесты

Из корня репозитория:

```bash
python3 .tests/test_docker_assignment.py
```

Нужны Python 3.10+, работающий локальный Docker с Compose и доступ к образу PostgreSQL 18. Python-зависимости устанавливать не требуется.

Проверяются:

1. Два сервиса, PostgreSQL 18, настройки, публикация порта, healthcheck и правильные mounts.
2. Схема таблицы и три начальные записи.
3. SQL-запрос из отдельного контейнера и отказ при неверном пароле.
4. Сохранность дополнительной записи после `down` / `up`; клиент должен вернуть уже `4`.

Тесты копируют файлы задания во временную папку, создают отдельный проект с уникальным именем, подставляют свободный порт через `PG_PORT=0` и после проверки удаляют его ресурсы. Ваш рабочий проект остаётся отдельным.

GitHub Actions запускает ту же проверку при push и Pull Request. Для сдачи сохраните Compose, SQL и `.env.example` в репозитории.
